> 我在翻 One Page Love 找设计灵感的时候，瞥见了这个站点。
> 页面加载完，第一反应是：怎么**几乎没有交互**？滚动不带动画、图片不弹窗、文字没有花哨的效果。
> 但我盯了十秒钟，又觉得——**也许这才是对的。**

Daru Sim 是一位有 13 年经验的产品设计师，这是他个人作品集网站。一眼看去就是"设计师的克制审美"——大留白、双版本截图、干净的字体。

但对于做技术的我来说，更关心的是它的**实现方式**。看起来只是一个静态页面，结果一拆解发现，表面越是简单，背后的技术取舍越有意思。

---

## 表面印象

打开页面，你能数得出来的"功能"不超过一只手：

- 一段自我介绍 + 三个按钮（复制邮箱、LinkedIn、简历）
- 几个作品集分区，每个分区一网格截图
- 右上角一个亮/暗模式切换
- 没了。真的是全部。

但这恰恰是最高级的地方：**所有的注意力都留给了作品本身。**

每一张截图都在说话，设计师不需要浏览器弹窗、不需要视频自动播放、不需要悬停特效——图片铺开，你自己看。

---

## 技术拆解

### 🏗️ 构建工具：Astro

站点使用 [Astro](https://astro.build/) 构建——一个现代的静态站点生成器，但它有一个标志性的特性叫 **群岛架构**（Islands Architecture）。

简单说就是：页面的大部分内容编译成纯静态 HTML，只有需要交互的"孤岛"组件才会加载 JavaScript。这样做的好处是：

- **首屏极快**——90% 以上的页面不需要 JS 水合
- **包大小可控**——只有交互组件才带 JS，页面静态部分就是纯粹的 HTML+CSS

这个站点一共只用了 **2 个 Astro Island**，全部采用 `client:visible` 策略——组件在进入视口后才水合，懒加载到极致。

### ☀️ 主题切换：双系统并行

亮/暗切换是一个很有趣的案例。它实现了**双层检测**：

```
第一层（自动）：时区判断
   根据用户所在地的当前时间（Asia/Kuala_Lumpur），
   19:00~07:00 自动切到暗色模式

第二层（手动）：按钮切换
   右上角的太阳/月亮按钮，用户可以手动覆盖
   使用自定义 radio group，纯 SVG 图标
```

更值得一提的是，**每个项目截图都准备了 light 和 dark 两个版本**：

```
airbase-1-light.webp     airbase-1-dark.webp
airbase-2-light.webp     airbase-2-dark.webp
...
```

CSS 根据当前主题状态切换显示对应的图片。这个"双图策略"显然增加了工作量（设计师得导出两套截图），但效果非常统一——暗色模式下亮色的工具栏不会刺眼，亮色模式下暗色的界面也不会显得突兀。

### 🎨 样式体系：纯 CSS + 变量

这是一个值得注意的选择——站点没有用 Tailwind、没有用 SCSS、没有 CSS-in-JS。

所有样式通过 **CSS 自定义属性**（变量）管理主题和颜色：

```css
:root {
  --color-bg: #FFFFFF;
  --color-text: #1A1A1A;
  --color-text-muted: #6B6B6B;
  --color-surface: #F5F5F5;
}

html.dark {
  --color-bg: #0A0A0A;
  --color-text: #EDEDED;
  --color-text-muted: #A0A0A0;
  --color-surface: #1A1A1A;
}
```

全部编译到一个哈希化的 CSS 文件里，没有框架的开销，干净利落。

### 🖼️ 图片策略：为什么它加载得这么快

这个站点有 **80 张截图**，但加载速度一点不慢。原因是：

1. **全部使用 `loading="lazy"`** — 懒加载，只有进入视口的图片才请求
2. **WebP 格式** — 比 PNG/JPG 小得多
3. **CSS `object-fit: contain`** — 图片自适应容器，不会有变形
4. **没有花哨的图片弹窗/灯箱** — 不用加载额外的 JS 库

### 🚀 部署：Vercel

通过 Vercel 部署，集成了 **Web Analytics** 和 **Speed Insights**。这些脚本也是懒加载的，不影响首屏性能。

## 如果换一种实现方式？

我一边拆一边想，这个站点如果用别的技术栈会怎么样：

| 场景 | 当前方案 (Astro) | React/Gatsby | 纯 HTML |
|------|------------------|--------------|---------|
| 主题切换 | Astro island (2KB JS) | 整站水合 (~50KB+) | 只能靠纯 CSS |
| 首屏 JS | ≈ 0 | 框架运行时 | 0 |
| 图片管理 | 手动双版本 | 可自动化 | 手动 |
| 开发体验 | 组件化 + Markdown | 组件化 | 需要模板引擎 |

Astro 在这个场景下是 **甜点选择**——不需要 React 那种重型框架，但也不想回到纯 HTML 手动拼页面的时代。群岛架构让"大部分静态、少部分交互"的模式变得特别自然。

---

## 一句话总结

这个站点让我想起一句话：**"好的设计就是没什么可去掉的。"**

它没有用任何冗余的技术——没有动画库、没有前端框架、没有弹窗组件——但该有的功能一个不少。80 张图片的懒加载、亮暗两套截图、无感知的主题切换……这些"看不见"的工作量，比任何花哨的动效都更值钱。

如果你在做一个作品集网站，Daru Sim 的案例是一个很好的参考：**先想清楚哪些东西不应该存在，再想想需要的部分怎么做得更好。**
